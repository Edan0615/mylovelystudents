本堂課我們將踏入後端開發的世界！透過生動的「學校行政處室」比喻，快速搞懂 MVC 架構，並完成本地開發環境所需的所有軟體安裝。

我們以前寫前端，跟現在學「後端」有什麼不同？

以前我們寫前端網頁（HTML / CSS / JavaScript），通常只需要用瀏覽器直接點開 HTML 檔案就可以運作。因為瀏覽器天生就懂得如何去解析、渲染這些前端的標籤與樣式。

但是，後端（如 PHP 框架 Laravel）截然不同！後端需要處理的是資料庫的讀寫、伺服器端邏輯的運算、權限管理與複雜的 API 路由。

為什麼不能直接點開網頁？

因為 PHP 是在「伺服器端」執行的程式語言。在傳送給瀏覽器之前，必須先經過伺服器環境的編譯和处理，將結果轉成 HTML。因此，我們需要在電腦中架設一個「模擬伺服器環境」（XAMPP）來幫我們執行 PHP 程式碼。

前端 vs 後端 快速對照表

前端開發 (Frontend)

處理外觀、特效、使用者的互動。只要瀏覽器即可運作。

後端開發 (Backend)

處理資料庫、伺服器邏輯、安全驗證。需要 PHP 執行環境與伺服器伺服軟體。

新手必看：為什麼學習 PHP 與 Laravel 是你的最佳選擇？

1

PHP：專為網頁而生的語言，好學好懂

與 Python、Java 等通用語言相比，PHP 從一誕生就是為了建構網頁而設計的。它的語法非常直覺，接近 JavaScript，讓網頁新手能無痛銜接後端邏輯。

2

龐大的社群與資源，不怕遇到問題沒人問

全球有超過 70% 的網站都在使用 PHP（包括著名的 WordPress）。這代表著網路上有鋪天蓋地的教學、問答與開源套件，任何你踩過的坑，前人早就幫你填好了。

3

Laravel：「網頁工匠」的優雅寫法

Laravel 被譽為最優雅的 PHP 框架。它的程式碼讀起來就像英文一樣流暢，強迫開發者使用現代、乾淨的程式設計模式，能幫你在學習初期就養成良好的寫 code 習慣。

4

功能內建免重複造輪子，一秒解鎖專業功能

註冊登入、發送電子郵件、資料庫串接、分頁處理等，Laravel 全都幫你內建好了。新手不需要花費數週去手寫安全驗證，可以把精力集中在核心的業務邏輯，成就感滿滿！

「Laravel 不僅僅是個框架，它為新手開發者打開了一扇通往現代軟體工程設計（如 MVC、依賴注入、ORM）的大門，是從『寫網頁』跨入『系統開發』的最佳跳板。」

工欲善其事，必先利其器：後端環境配置三劍客

在開始開發 Laravel 之前，我們必須在電腦中配置以下三種核心工具

1. XAMPP (伺服器與資料庫)

XAMPP 是一個整合型的軟體套件，安裝後可以一次取得 Apache 網頁伺服器 以及 MariaDB (MySQL) 資料庫，同時內建 PHP 執行環境。它能讓你的電腦瞬間變身成一台後端伺服器！

前往下載 XAMPP

2. Composer (PHP 套件管理工具)

就像 Node.js 的 npm 一樣，Composer 是 PHP 世界的套件管理老大。當我們要安裝 Laravel 框架、或者使用別人寫好的開源功能（例如發信、後台管理套件）時，都是交給 Composer 來幫我們下載與管理。

前往下載 Composer

3. Node.js & npm (前端編譯工具)

奇怪，我們不是在寫後端嗎？為什麼要裝 Node.js？因為現代後端開發（包括 Laravel）通常內建了前端資源打包工具（如 Vite 或者是 Laravel Mix）。我們需要 npm 來幫我們編譯 CSS/JS 或是安裝前端 UI 庫。

前往下載 Node.js
生動比喻 · 輕鬆記憶

如果 Laravel 是一所學校：行政處室的大分工

我們用學校的運作方式，來對比 Laravel 後端各個組件的功用與職責：

Route 路由

比喻：大門收發室 / 警衛

當有訪客（使用者瀏覽器發送 Request）來到學校時，警衛是第一個接觸的人。警衛會看你手上的公文（網址 URL），決定你要去哪個處室。

網址輸入 /students -> 警衛指引至「學生處」
Controller 控制器

比喻：教務處 / 總務處處長

他是核心主管！收到警衛傳過來的訪客後，負責調配工作。他自己不搬資料，但他會叫「檔案管理員」（Model）去查資料，並把資料拿去交給「佈告欄設計師」（View）排版。

接收請求 -> 呼叫 Model -> 將資料傳給 View
Model 模型

比喻：檔案室管理員

只負責管理學校的所有學生檔案與教職員資料庫。他聽從 Controller 處長的指示，去抽屜裡拿出需要的學生檔案，或者將新的檔案放進保管箱。

Student::where('grade', 3)->get();
View 視圖

比喻：大門口佈告欄 / 黑板

這是呈現給外來訪客看的地方。設計師會依據處長（Controller）給的資料，排版成漂亮的畫面（HTML/Blade），讓來看的人一目瞭然。

<h1>哈囉，{{ $student->name }}</h1>
Migration 遷移

比喻：校舍改建與裝潢工程圖

當學校要蓋一間新的教室（在資料庫建立新的資料表），或者是要幫教室加蓋一個隔間（增加欄位），都要先畫好施工藍圖（Migration），並發布給施工團隊執行。

php artisan migrate (執行施工圖)
Request / Response

比喻：家長來信與學校回覆公文

Request（請求）就是訪客寄信問學校問題；而學校處理完畢後，回送給訪客的答覆信件與成績單就是 Response（回應）。

Request (瀏覽) -> 伺服器處理 -> Response (HTML網頁)

深度解析：MVC 設計模式與 Migration 的力量

MVC 設計模式

MVC 是一種軟體設計架構，它將程式碼分成三個核心區塊：

  • M Model (模型)： 負責資料的邏輯。在這裡我們定義資料的格式，與資料庫進行 CRUD (新增、讀取、更新、刪除) 的溝通。
  • V View (視圖)： 負責呈現外觀。在 Laravel 中通常使用 .blade.php 模板檔案來渲染畫面。
  • C Controller (控制器)： 負責調度。當路由把請求送過來，Controller 會去拿 Model 的資料，做必要運算後，丟給 View 渲染網頁。

Migration (資料庫遷移) 的妙處

在以前，我們如果要建資料表，可能需要手動在 PHPMyAdmin 打開網頁操作，或者自己寫 SQL 指令。但在團隊合作時，別人根本不知道你新增了什麼欄位。

Migration 就像是「資料庫的 Git 版本控制」。我們用 PHP 程式碼來寫資料表的欄位定義。只要你寫好 Migration，你的隊友只需要在終端機輸入：

php artisan migrate

他的資料庫就會自動同步建立跟你一模一樣的欄位與資料表，非常方便！

實戰目標

認識 Laravel Voyager：一秒生成精美的後台管理系統

Voyager 是 Laravel 一個極具人氣的開源後台管理套件（Admin Package）。它提供了完整的 BREAD (Browse, Read, Edit, Add, Delete) 操作介面，讓我們不用寫半行代碼就能透過網頁操作資料表。

在我們的專案中，學習 Laravel Voyager 的作用是幫助我們快速搭建一個「可視化後台」，方便朱珮瑜同學在接下來的課程中，可以直觀地理解資料庫、權限、選單是如何在 Laravel 中運作的。

Voyager 官網 Voyager GitHub 倉庫
Terminal - Composer Install

# 1. 下載 Voyager 套件

$ composer require tcg/voyager

# 2. 執行安裝指令 (包含示範資料)

$ php artisan voyager:install --with-dummy

# 3. 啟動本機伺服器

$ php artisan serve
