設計心法補充

思考：為什麼學習後端，也是在設計「使用者介面 (UI/UX)」？

介面設計不只是畫出漂亮的 Figma 畫面，更是在定義系統與使用者的互動方式。懂後端的設計師，能規劃出真正合理且體驗順暢的流程。以下是我們這堂課的技術，如何與介面設計產生深刻關聯：

1. RESTful API & 路由 ➔ API 介面設計 (DX)

網址 (URL) 其實就是前端或開發者跟後端溝通的「文字介面」。乾淨、有規律的路由（如 GET /students）能提供極佳的開發者體驗 (Developer Experience)，讓串接過程順暢無阻。

2. Controller ➔ 互動體驗 (UX) 設計

Controller 掌握了流程。當表單輸入錯誤時退回並顯示「紅色錯誤提示」，或成功後引導至新畫面並顯示「綠色成功彈窗」，這些回饋機制 (Feedback) 都是 UX 互動設計的核心。

3. Migration ➔ 資訊架構 (IA) 與輸入元件

資料庫欄位直接決定了介面元件：boolean 欄位對應 UI 的 Toggle 開關；date 欄位對應 **日曆選取器**。Migration 實質上就是在為介面做資訊架構與輸入限制的底層規劃。

4. Blade 模板 ➔ 元件化與視覺一致性

Blade 的主外框繼承（Layouts）與元件封裝，概念完全對應 Figma 的 **Components（元件）**。透過將重複的按鈕與卡片模組化，能大幅確保軟體產品的視覺一致性與開發效率。

Chapter 01

RESTful API 設計與 HTTP 基礎

RESTful API 是一種引領現代網頁設計的架構風格，也是「前後端分離」的核心。它利用標準的 HTTP 方法，搭配直觀、語意化的資源網址 (URL) 來操作資料。

什麼是 HTTP？(用生活例子秒懂)

HTTP (超文字傳輸協定) 是網頁世界的「溝通語言與約定」。
想像我們兩個人要開會溝通，如果一個人講中文、另一個講英文，卻沒有事先說好要用哪種語言，就完全無法交流。HTTP 就是大家說好在網路上傳遞資料的「語言協定」。瀏覽器與伺服器之間只要都遵守 HTTP 的規範，就能互相聽懂、順利傳遞網頁與圖片。

HTTPS HTTP + S (Secure 安全版)。把原本傳送的語言「加密」，防止中間有人偷聽或修改，是現代所有網站的基本標準。

RESTful 資源動作對照表 (Resource Actions Mapping)

在 Laravel 中，當我們宣告一個資源路由（例如學生資料 students），會自動對應 7 個標準的 Controller 動作方法：

HTTP 方法 URI (路徑) Action (對應方法) Route Name (路由名稱) 功能描述說明
GET /students index students.index 取得並顯示所有學生名單頁面 (R)
GET /students/create create students.create 回傳「新增學生」的 HTML 輸入表單頁面
POST /students store students.store 將表單提交的資料「寫入 / 新增」到資料庫 (C)
GET /students/{student} show students.show 顯示特定一筆學生的詳細詳細資料頁面 (R)
GET /students/{student}/edit edit students.edit 回傳「編輯資料」的 HTML 修改表單頁面
PUT/PATCH /students/{student} update students.update 接收編輯資料表單，進行資料「更新」動作 (U)
DELETE /students/{student} destroy students.destroy 執行將特定學生資料「刪除」的動作 (D)

Chapter 02

web.php 路由管理

路由路徑（Route）就像是網站的門牌號碼。當瀏覽器發出請求時，routes/web.php 決定該由誰來處理。

常見的 HTTP 方法 (Methods) routes/web.php

當使用者在網址列輸入網址，或者點擊連結時，送出的都是 GET 請求。用於「讀取」資源。 

// 簡單回傳視圖 (Blade)
Route::get('/welcome', function () {
    return view('welcome');
});

// 指向 Controller 處理
Route::get('/students', [StudentController::class, 'index']);

當使用者填寫表單並按下「送出」時，使用 POST 請求。在 Laravel 中，POST 請求表單內必須包含 @csrf 保護標記，否則會報錯（419 page expired）。 

// 新增學生資料的處理路由
Route::post('/students', [StudentController::class, 'store']);

PUT 用於替換整筆資源，而 PATCH 用於修改部分欄位。在 HTML 表單中，因為瀏覽器只支援 GET 與 POST，所以需要透過 @method('PATCH') 進行偽裝。 

// 修改 ID 為 5 的學生資料
Route::patch('/students/{id}', [StudentController::class, 'update']);

DELETE 用於移除伺服器上的某個資源。與 PATCH 相同，在 HTML 表單中需要寫成 POST，再利用 @method('DELETE') 偽裝。 

// 刪除 ID 為 5 的學生資料
Route::delete('/students/{id}', [StudentController::class, 'destroy']);

Chapter 03

Controller 控制器

Controller 是網站的「大腦」。它負責接收路由送來的請求，去資料庫撈取資料，處理邏輯，最後把資料塞進 Blade 視圖並呈現在使用者眼前。

1. Resource 資源控制器

一次幫你生成 CRUD (增刪改查) 所需的 7 個標準方法，自動對應我們 Chapter 01 介紹的 RESTful 規範。

php artisan make:controller StudentController --resource

2. Single Action Controller

如果這個 Controller 只需要處理「一件事」（例如：發送電子報），可以使用 __invoke 單一方法控制器。

php artisan make:controller SendNewsletterController --invokable

資源控制器 (Resource Controller) 的 7 個方法功能詳細說明

1. index() - 列表頁面

負責至資料庫撈取所有或分頁資料，並將資料陣列傳遞至前台 Blade 視圖中，印出列表畫面。

2. create() - 新增表單

不處理任何資料庫寫入。純粹回傳一個空白的 HTML 輸入表單頁面，供使用者填寫資料。

3. store(Request $request) - 執行儲存

接收來自 create 表單送出的 POST 資料，執行欄位格式驗證 (Validation)，隨後寫入資料庫並重新導向頁面。

4. show($id) - 詳細頁面

依據傳入的特定 ID，去資料庫找尋單一筆特定資料（如指定學生的個人資訊），並將該筆資料單獨呈現在頁面上。

5. edit($id) - 編輯表單

依據特定 ID 撈出舊資料，並回傳一個帶有舊資料欄位值（Value）的 HTML 修改表單頁面供使用者修改。

6. update(Request $request, $id) - 執行更新

接收來自 edit 表單送出的 PUT/PATCH 修改資料，進行欄位驗證後，直接修改/更新資料庫內對應的資料欄位。

7. destroy($id) - 執行刪除

依據傳入的特定 ID，直接呼叫資料庫刪除該筆記錄，執行成功後重新導向至列表頁面並附帶成功訊息。

資源控制器 7 個預設方法範例 app/Http/Controllers/StudentController.php 
namespace App\Http\Controllers;

use App\Models\Student;
use Illuminate\Http\Request;

class StudentController extends Controller
{
    // 1. 列表頁面：GET /students (對應 index)
    public function index()
    {
        $students = Student::all(); 
        return view('students.index', compact('students'));
    }

    // 2. 新增表單：GET /students/create (對應 create)
    public function create()
    {
        return view('students.create'); // 回傳新增學生資料的表單畫面
    }

    // 3. 儲存動作：POST /students (對應 store)
    public function store(Request $request)
    {
        $validated = $request->validate([
            'name' => 'required|max:50',
            'score' => 'required|integer|min:0|max:100',
        ]);

        Student::create($validated); 
        return redirect()->route('students.index')->with('success', '建立學生成功！');
    }

    // 4. 詳細頁面：GET /students/{id} (對應 show)
    public function show($id)
    {
        $student = Student::findOrFail($id); // 找尋該學生，找不到則丟出 404 錯誤
        return view('students.show', compact('student'));
    }

    // 5. 編輯表單：GET /students/{id}/edit (對應 edit)
    public function edit($id)
    {
        $student = Student::findOrFail($id);
        return view('students.edit', compact('student'));
    }

    // 6. 更新動作：PUT/PATCH /students/{id} (對應 update)
    public function update(Request $request, $id)
    {
        $validated = $request->validate([
            'name' => 'required|max:50',
            'score' => 'required|integer|min:0|max:100',
        ]);

        $student = Student::findOrFail($id);
        $student->update($validated); // 更新資料庫資料

        return redirect()->route('students.index')->with('success', '資料更新成功！');
    }

    // 7. 刪除動作：DELETE /students/{id} (對應 destroy)
    public function destroy($id)
    {
        $student = Student::findOrFail($id);
        $student->delete(); // 刪除資料

        return redirect()->route('students.index')->with('success', '學生已成功刪除！');
    }
}

Chapter 04

Migration 資料庫遷移

Migration 就像是資料庫的「版本控制系統」(Git)。它用程式碼記錄了資料表的建立與欄位修改，讓團隊所有人的資料庫結構都能完全一致。

資料庫遷移常用指令

1. 建立 Migration

建立一個名為 students 的資料表遷移檔。

php artisan make:migration create_students_table
2. 執行遷移

將所有尚未執行的遷移檔套用到資料庫中。

php artisan migrate
3. 倒回重來

還原上一次執行過的 migration 動作。

php artisan migrate:rollback

常見 Migration 欄位型態與修飾詞對照表

Migration 語法寫法 對應 SQL 資料型態 常見用途說明 常用搭配修飾詞 (Modifiers)
$table->id() BIGINT AUTO_INCREMENT 自動遞增的主鍵 ID。每張表必備的首個欄位。 無
$table->string('name', 50) VARCHAR(50) 儲存長度受限的短文字。如：姓名、電話、密碼。 ->unique() 欄位值不可重複
$table->integer('score') INT 儲存一般整數。如：年齡、分數、庫存數量。 ->default(0) 設定預設值
$table->text('biography') TEXT 儲存長篇文字、大段落。如：文章內文、備註說明。 ->nullable() 允許欄位為空 (NULL)
$table->boolean('is_active') TINYINT(1) 儲存布林值（真/假，1/0）。如：開關狀態、是否已讀。 ->default(true)
$table->decimal('price', 8, 2) DECIMAL(8, 2) 高精度小數。適合儲存金錢、比例（共 8 位，包含 2 位小數）。 ->default(0.00)
$table->date('published_at') DATE 僅儲存日期（年-月-日）。如：生日、出刊日期。 ->nullable()
$table->foreignId('user_id') BIGINT (FOREIGN KEY) 建立資料庫外鍵關聯。與另一張表的主鍵連線。 ->constrained()->onDelete('cascade')
$table->timestamps() TIMESTAMP (2 columns) 自動建立 `created_at` 與 `updated_at` 記錄寫入與修改時間。 無
常用欄位型態與結構範例 database/migrations/xxxx_create_students_table.php

在 up() 方法中定義你的資料表與欄位型態： 

Schema::create('students', function (Blueprint $table) {
    $table->id();                                  // 自動遞增的 ID 主鍵 (BigInteger)
    $table->string('name', 50);                    // 字串欄位 (VARCHAR)，長度 50
    $table->integer('score')->default(0);          // 整數欄位，預設值為 0
    $table->text('biography')->nullable();         // 長文字欄位，允許為空值 (NULL)
    $table->boolean('is_active')->default(true);   // 布林值，預設為 true
    
    // 外部鍵關聯：這名學生屬於某個班級 (classes 資料表)
    $table->foreignId('class_id')->constrained()->onDelete('cascade');
    
    $table->timestamps();                          // 自動建立 created_at 與 updated_at
});

Chapter 05

Blade 模板引擎

Blade 是 Laravel 的精緻前台渲染引擎。它把乾淨的 HTML 結合特殊的 directives (指令)，讓你能夠輕鬆印出變數、進行邏輯判斷與迴圈輸出。

Blade 基本語法展示 resources/views/students/index.blade.php 
@extends('layouts.app') {{-- 繼承主外框 layouts/app.blade.php --}}

@section('content') {{-- 把這段內容塞入主外框的 @yield('content') 中 --}}
    <div class="container">
        <h1>學生名單</h1>
        
        {{-- 判斷式 --}}
        @if($students->isEmpty())
            <p>目前沒有任何學生。</p>
        @else
            <ul>
                {{-- 迴圈印出 --}}
                @foreach($students as $student)
                    <li>
                        {{-- 印出變數 --}}
                        {{ $student->name }} - 成績: {{ $student->score }} 分
                    </li>
                @endforeach
            </ul>
        @endif
    </div>
@endsection

主外框與子頁面的繼承概念 (Layout & Yield)

1. 主外框 layouts/app.blade.php 
<html>
  <body>
     <nav>導覽列</nav>
     
     @yield('content')
     
     <footer>頁尾</footer>
  </body>
</html>
2. 子視圖 views/index.blade.php 
@extends('layouts.app')

@section('content')
  <p>我是真正的頁面網頁內容。</p>
@endsection
